# GitHub 双平台发布、数据隔离与更新提示

用户目标：把现有学习软件上传到 https://github.com/frostloom/study.git，发布Mac/Windows安装版本；真实日常学习转到本机应用，开发可独立预览；安装过的正式版本能在左下角看到新版更新按钮。

## 实现决定（由实现者选择）
- 延用HTML/CSS/JS前端、冻结Python后端及轻量原生外壳。macOS继续AppKit/WKWebView；Windows使用Win32/WebView2外壳。Windows目标为Win10/11 x64；Mac发布arm64与Intel x64包，通过对应GitHub托管runner构建。若实际runner不支持某架构，明确报告而不伪装已完成。
- 正式版数据：macOS既有Application Support/日常学习；Windows使用LOCALAPPDATA/DailyStudy。预览版使用独立名称、bundle/app ID、WebView存储和数据路径，不自动导入真实学习资料，也不运行真实学习定时器。开发源码放用户日常学习目录下独立开发目录，正式.app单独安装。
- GitHub仓库仅放应用源码、测试、依赖锁定、图标、文档及CI配置；不上传个人资料、数据库、模型地址/密钥或旧私有备份，不覆盖远端已有内容。私有数据在任何git add前检查。
- 版本统一来源。推送版本tag触发Mac和Windows测试/构建；全部成功后生成GitHubRelease、安装附件及SHA256清单。正式更新检查仅看stable/latest，不把草稿/预发布推给正式用户。
- 左下角平时不展示更新按钮；启动后自动后台检查，运行期间每6小时自动检查、按时间缓存。发现较新且匹配平台的正式附件后自动出现“有新版本，立即更新”，点击弹窗展示版本说明、下载按钮。下载走GitHubHTTPS公开Release附件；失败可重试。先做用户主动下载安装，不自动替换运行中的应用，不自行增加后台服务。保留本地数据即可在覆盖应用后继续学习。
- 使用原生外链打开下载，受限于同一正式仓库及HTTPS；不接受远端任意脚本/命令。离线不阻塞学习。预览版明显标识，不提示正式版更新，避免误装。

## 本机迁移
- 写入前分别做SQLite一致性备份及必要设置备份，读取现状、核对差异；两套已经相同的数据不重复覆盖。若发现双方都有新记录，保留并合并，冲突不得静默丢弃。
- 把网页旧模型配置、日程、档案偏好迁移到正式版；兼容API原样保留，不上传也不显示密钥。连接验证需真实请求，只有明确成功才写verified，不伪造成功。
- 浏览器localStorage中的主题、会话选择及未提交问答草稿，通过用户当前本机网页读取并导入桌面浏览器存储；保留原存储为恢复来源。迁移记录可核对。
- 旧“启动学习台.command”备份后改为打开正式应用；关闭已识别旧学习网页后端，保留旧源码/原资料可恢复。不影响任何GPT、实习或个人项目进程。

## 验收与边界
- 自动测试覆盖Windows/Unix目录锁和父进程检测、版本比较、离线/错误Release数据、稳定版过滤、平台附件选择、迁移及两环境隔离。
- 本机测试最终Mac包真实数据/独立预览、更新对话框、重启、原资料完整性。GitHubCI在Windows实际运行冻结后端与原生外壳启动烟测；不能将跨平台代码存在当作Windows已验证。
- 上传及创建Release已经由用户本轮明确授权，无需再为推送/发布单独确认。
- 现有Mac采用ad-hoc签名，没有DeveloperID/公证凭据。Windows无签名证书。软件可生成并发布，但系统可能提示未验证发行者；不擅自降低系统防护。正式代码签名属于需用户证书的后续限制。
